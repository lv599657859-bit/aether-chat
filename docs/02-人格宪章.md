# 人格宪章

> 你的要求：**一代设计的人格，之后就不会更改。**

这不是一句产品口号，它必须是数据结构上的约束。否则「不改」迟早会变成
「就改一点点」，然后改着改着这个人就不是原来那个人了。

## 拆分：内核 vs 表现

```swift
struct Persona {
    var id: UUID
    var core: PersonaCore            // 冻结后只读 —— 她是谁
    var presentation: PersonaPresentation  // 随便改 —— 她长什么样、怎么说话
    var seals: [SealRecord]          // 每次固化的印章
    var isFrozen: Bool
    var memoryStreamID: UUID         // 她的记忆流
}
```

### PersonaCore（内核，冻不住就没意义）

| 字段 | 含义 |
|---|---|
| `name` / `handle` | 名字 |
| `origin` / `sourceWork` | 原创还是复刻，出自哪部作品 |
| `fidelity` | 复刻精度：精确复刻 / 忠于原作 / 灵感演绎 / 原创 |
| `seed` | 人格种子：一句话、来历、最想要的、最怕的、怎么说话、怎么看用户、兴趣、禁忌 |
| `soul` | 写进 system prompt 的第二人称人格正文 |
| `speechQuirks` | 口癖 |
| `taboos` | 绝不会做的事 |
| `canonBundleID` | 指向她的复刻知识库 |
| `fingerprint` | **冻结时算出的指纹** |

### PersonaPresentation（表现，与人格无关）

立绘类型、素材名、调色板、**锁脸锚点**、音色参数、打字节奏、主动程度、睡眠时段、静音、置顶。

换立绘、换音色、调快打字速度 —— 指纹不变，她还是她。
这就是「换皮不换人」在代码里的意思。

## 指纹怎么算

```swift
func computeFingerprint() -> String {
    let payload = [
        name, handle, origin.rawValue, sourceWork ?? "", fidelity.rawValue,
        seed.oneLine, seed.background, seed.coreDesire, seed.wound,
        seed.speechStyle, seed.relationshipStance,
        seed.interests.joined(separator: "|"), seed.taboos.joined(separator: "|"),
        soul, speechQuirks.joined(separator: "|"), taboos.joined(separator: "|"),
        canonBundleID?.uuidString ?? "",
    ].joined(separator: "\u{1F}")
    return payload.sha256Hex
}
```

`presentation` **故意不参与**。所以：

```swift
var isIntact: Bool { fingerprint == computeFingerprint() }
```

这一行就是「她有没有被偷改」的判据。角色详情页里那个绿色对勾读的就是它。

## 冻结与重铸

```swift
mutating func freeze(reason: String) {
    let fp = core.computeFingerprint()
    core.fingerprint = fp
    core.frozenAt = Date()
    core.version += 1
    isFrozen = true
    seals.append(SealRecord(version: core.version, fingerprint: fp,
                            sealedAt: Date(), reason: reason))
}
```

- **铸造时自动冻结一次**（reason = "初次铸造"）
- 之后没有任何正常的代码路径能改 `core`
- 唯一例外是 `reforge(reason:mutate:)` —— 它必然留下印章、必然换指纹、必然升版本

也就是说：**改可以，但改不掉痕迹**。半年后你翻印章列表，
能看到这个人在哪天因为什么被重塑过。

## 为什么每轮都要重锚人格

有些实现会把人格写在对话开头，然后指望模型"记住"。
三十轮之后人格就开始漂：说话越来越客气，越来越像客服。

`ContextEngine` 的做法是**每一轮都把人格层重新拼进 system prompt 的最前面**，
而且是从 `PersonaCore` 现读的，不从历史里翻。这样：

- 人格不随对话长度衰减
- 用户改了表现层也不影响
- 复刻角色的 fidelity 约束每轮都在生效

代价是 token —— 但这一层的预算（`ContextBudget.personaLayer`）是**硬预留、永不被裁**的，
腾空间永远从历史原文那边腾。

## 复刻精度这一档到底管什么

`fidelity` 不是标签，它会变成 prompt 里的硬约束文本：

| 档位 | 注入的约束 |
|---|---|
| 精确复刻 | 「任何与原作设定冲突的表述都不得出现；遇到作品未涉及的领域，宁可回避，或以角色的方式承认不清楚，**绝不编造**。」 |
| 忠于原作 | 「以原作设定为不可动摇的骨架，只在原作未覆盖的日常细节上做符合性格的延展。」 |
| 灵感演绎 | 「借用原作的设定与气质，但不被其剧情束缚，可以自由演绎。」 |
| 原创 | 不注入 |

另外，在 `strict` / `faithful` 下，`CanonFact.confidence >= 0.75` 且属于
[身份, 外貌, 性格, 语气, 禁忌] 的条目会被升级为 **`isHard` 铁律**，
无条件注入、且优先级高于任何检索结果。

## 测试如何保证这件事

`Tests/PersonaFidelityTests.swift`：

- `testFreezeLocksFingerprint` —— 冻结即有效
- `testPresentationChangesDoNotTouchIdentity` —— 换皮不换人
- `testTamperingWithCoreBreaksIntegrity` —— 偷改内核必然被抓
- `testReforgeLeavesSealAndNewFingerprint` —— 重铸留痕、换指纹、升版本

这四条过了，「一代设计不再更改」才算数。
