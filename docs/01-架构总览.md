# 架构总览

## 一条消息的完整旅程

用户在输入框打了一句「我今天有点累」，按下发送。接下来 3 秒内发生的事：

```
Composer
  └─ ChatViewModel.send(text:)
       └─ ChatOrchestrator.send(in:)
            │
            ├─ 1. 用户消息落库（WorldStore.append）
            │     └─ 广播 .messagesChanged → 界面刷新
            │
            ├─ 2. 关系推进（RelationshipEngine.updateUserEdge）
            │     └─ 「我累」命中了"倾诉"信号 → 信任 +0.09，熟悉 +0.04
            │
            ├─ 3. 组装上下文（ContextEngine.workingSet）
            │     ├─ 第1层 人格：soul + 口癖 + 禁忌 + 复刻约束（每轮重锚，不靠模型记）
            │     ├─ 第2层 canon：按当前话题向量检索出的原作事实 + 铁律
            │     ├─ 第3层 记忆：向量 × 显著度 × 时近性 混合排序取 top-k
            │     ├─ 第4层 关系：五维数值翻译成语气指令
            │     ├─ 第5层 演出协议：把可用动作白名单写进 prompt
            │     ├─ 第6层 沉浸守门：绝对禁令
            │     └─ 第7层 连续性：滚动摘要 + 摘要覆盖点之后的原文窗口
            │
            ├─ 4. 流式生成（ProviderHub.llm.stream）
            │
            ├─ 5. 边生成边解析（CueStreamParser.feed）
            │     ├─ 正文 → 屏幕
            │     ├─ ⟦c:…⟧ → PerformanceDirector → 立绘/舞台/触感/环境音
            │     ├─ ⟦e:…⟧ → EmotionState → AvatarCoordinator（插值平滑）
            │     ├─ ⟦m:…⟧ → 只进 HiddenTrace，永不显示
            │     └─ ⟦c:pacing.split⟧ → 把前面那段话作为独立气泡发出去
            │
            ├─ 6. 沉浸守门擦除（ImmersionGuard.scrub）
            │     └─ 「作为一个AI…」→ 整句删除，并计数 oocBlocks
            │
            ├─ 7. 落库 + 回填 HiddenTrace（token / 记忆ID / 独白 / 拦截数）
            │
            └─ 8. 后台维护（postProcess）
                  ├─ 记忆抽取（MemoryExtractor）
                  ├─ 压缩阈值到了 → 滚动摘要（Summarizer）
                  └─ 角色之间关系推演
```

## 分层原则

```
┌─────────────────────────────────────────────┐
│ Features/   界面。只认 Models，不认引擎细节   │
├─────────────────────────────────────────────┤
│ Orchestration/  编排。谁说话、说什么、说完之后 │
├─────────────────────────────────────────────┤
│ Memory / Canon / Effects / Avatar / Voice     │
│ 能力层。彼此不直接依赖，通过参数与协议组合     │
├─────────────────────────────────────────────┤
│ LLM / Persistence / Support  基础设施         │
├─────────────────────────────────────────────┤
│ Models/  纯值类型。零依赖，全部 Sendable      │
└─────────────────────────────────────────────┘
```

`Models/` 里没有一个 import 除了 Foundation。这是有意的：
人格、消息、关系、记忆这些概念不应该和任何框架绑死，
将来换 SwiftData、换引擎、甚至搬到服务端，它们都原样能用。

## 并发模型

- `WorldStore` 是 **actor**：所有世界状态读写都经过它，事件通过 `AsyncStream` 广播
- `FileStore` 是 **actor**：磁盘 IO 不阻塞主线程
- `MediaStore` 是 **actor**
- `ProviderHub` 是 `@unchecked Sendable` 的普通类：只在设置变更时重建
- 所有 UI 状态是 `@MainActor @Observable`
- `ChatOrchestrator` / `GroupDirector` / `AutonomyScheduler` 是 `@unchecked Sendable` 的编排器，
  通过 `AsyncStream` 把事件推给 `@MainActor` 的 ViewModel

这样做的好处：**流式生成永远不会卡住界面**，而界面也永远拿不到正在被修改的中间状态。

## Provider 抽象

```swift
protocol LLMProvider: AnyObject, Sendable {
    func stream(_ request: LLMRequest) -> AsyncThrowingStream<String, Error>
}
protocol ImageProvider: AnyObject, Sendable { … }
protocol EmbeddingProvider: AnyObject, Sendable { … }
protocol SpeechSynthesizer: AnyObject, Sendable { … }
protocol Transcriber: AnyObject, Sendable { … }
```

五个协议，五个维度。任何一个都能单独替换：

- 想用 Anthropic？实现 `LLMProvider`
- 想用本地 MLX 跑模型？实现 `LLMProvider`
- 想用 Stable Diffusion 出图？实现 `ImageProvider`
- 想接自训练 TTS 复刻原版声优？实现 `SpeechSynthesizer`

`ProviderHub` 负责根据设置组装这五个，其他代码全部通过它拿实例。

## 数据落地

```
Documents/
├── Aether/
│   ├── settings.json            全局设置
│   ├── personas.json            所有角色（含冻结指纹）
│   ├── conversations.json       会话（含摘要）
│   ├── edges.json               所有关系边
│   ├── intercharacter.json      幕间日志（只在潜意识层可见）
│   ├── messages/<会话ID>.json   消息（含隐藏轨迹）
│   ├── memories/<记忆流ID>.json 长期记忆（含向量）
│   ├── canon/<知识库ID>.json    复刻知识库
│   └── Media/                   图片与语音
│       ├── voice_*.m4a
│       ├── daily_*.jpg
│       └── user_*.jpg
└── AvatarModels/                用户导入的 3D 模型
```

没有数据库，没有云同步。所有东西都在沙盒里，删 app 就全没了 —— 这是刻意的。
