# 演出系统

> 你的要求：**有很多的演出效果。**

「很多」不是堆特效，是让**每一个情绪都有对应的表达通道**，而且这些通道互相协调。

## 核心判断：模型不该决定怎么演

如果直接让模型输出动画参数，会发生三件事：

1. 模型会编出不存在的动画名
2. 换一套形象方案（3D 换 2D）就得重写全部 prompt
3. 演出强度没法统一调节 —— 每个动作的幅度都散落在 prompt 里

所以中间加了一层**导演**：

```
模型想说「她害羞了」
      ↓ 只输出感觉
⟦e:v=0.7,a=0.8,d=0.3,label=羞恼⟧
⟦c:avatar.blush:0.7⟧
      ↓ PerformanceDirector 翻译
├─ 立绘：ParamCheek → 0.8，ParamEyeBallX → 偏移，ParamAngleZ → 6
├─ 或 3D：Expr_Blush 网格启用，头部微侧
├─ 或 光核：色相往暖偏，呼吸加快，脉冲一次
├─ 气泡：渐入
├─ 触感：UIImpactFeedbackGenerator(.light) 强度 0.7
└─ 舞台：不动（害羞不改变天气）
```

模型只表达「感觉」，引擎负责「怎么演」。这一层的价值在
`AvatarActionSemantics` 里体现得最清楚 —— 它给每个动作名定义了**跨实现一致的情绪意图**：

```swift
static func emotion(for action: String) -> EmotionState? {
    case "blush":    return EmotionState(valence: 0.6, arousal: 0.7, dominance: 0.3, labels: ["害羞"])
    case "lookaway": return EmotionState(valence: -0.1, arousal: 0.35, dominance: 0.35, labels: ["回避"])
    case "leanin":   return EmotionState(valence: 0.5, arousal: 0.5, dominance: 0.6, labels: ["靠近"])
    …
}
```

于是当 3D 模型没有 `blush` 这个动画时，它可以退化成"把表情调成害羞"，
演出不断线。

## 情绪是三维连续量，不是标签

```swift
struct EmotionState {
    var valence: Double    // -1 排斥 … +1 愉悦
    var arousal: Double    // 0 静 … 1 激动
    var dominance: Double  // 0 顺从 … 1 主导
    var labels: [String]   // 人话标签，给 UI 看
}
```

为什么不用 `enum Emotion { happy, sad, angry }`：

- **插值**。`blended(with:t:)` 让情绪能平滑过渡。上一句还生气，这一句心软了，
  表情是**渐变**过去的，不是瞬间切换。那半秒钟的过渡，就是"活"的来源。
- **组合**。「羞恼」= 高 arousal + 负 valence + 低 dominance；
  「故作镇定」= 正 valence + 低 arousal + 中性 dominance 但 label 说她在装。
  三种情绪混一混就有了，不用枚举。

`AvatarCoordinator` 以 30fps 心跳推进，每帧 `.apply(emotion:intensity:)` 一次，
运行时内部再做二次平滑（`t: 0.12~0.16`）。所以情绪**永远不是瞬变**。

## 演出指令协议

模型在台词里内嵌标记：

```
⟦c:channel.action:intensity⟧     动作
⟦e:v=0.7,a=0.8,d=0.4,label=羞恼⟧  情绪
⟦m:其实我早就不生气了⟧            内心独白（永不显示）
```

七个频道：

| 频道 | 动词（白名单） | 落到哪 |
|---|---|---|
| `avatar` | smile grin pout blush cry sulk surprise angry thinking lookaway nod shakehead tilt stretch shiver leanin stepback hug wave sigh yawn freeze | 立绘参数 / 3D 表情网格 / 光核变形 |
| `stage` | rain snow petals sparkle heartbeat glitch flash vignette blur sepia night sunset fireflies crack | 全屏 Canvas 特效 |
| `bubble` | shake typewriter fade slidein popin blur | 这一条气泡 |
| `audio` | rain_loop cafe_loop train_loop wind_loop heartbeat_sfx notification_sfx chime_sfx | AVAudioPlayer |
| `haptic` | light medium heavy success warning soft rigid | UIFeedbackGenerator |
| `camera` | pushin pullout shake tiltup dutch settle | 界面位移 |
| `pacing` | split | 拆成多条气泡 |

**白名单外的会被静默丢弃**（`CueVocabulary.isAllowed` 返回 false → `Log.stage.debug`）。
模型编新词不会崩，只是没效果。

### 流式解析：最容易出事的地方

`⟦c:avatar.blush⟧` 在网络流里可能被切成：

```
"今天" + "⟦c:ava" + "tar.smi" + "le:0.7⟧" + "很开心"
```

如果解析器只是 `replaceOccurrences`，中间那几片会直接漏到屏幕上 ——
用户看到 `⟦c:ava` 跟着文字一起打出来。沉浸感当场死亡。

所以 `CueStreamParser` 是一个**状态机**：进了 `⟦` 就进入 `inside = true`，
之后所有字符都进 buffer，直到遇见 `⟧` 才解析。没闭合就憋着不吐。

流结束时如果还有没闭合的（模型输出被截断了），`finish()` 会把 buffer
**原样当正文吐出来** —— 宁可多显示一点，也不吞掉用户该看到的内容。

这条规则有专门的测试：`testMarkerSplitAcrossChunksNeverLeaks`。

### 节拍：让真人感成立

`⟦c:pacing.split⟧` 是最重要的一个指令。它把一段话切成多条气泡：

```
⟦c:bubble.typewriter⟧⟦c:avatar.blush:0.7⟧今天…那个…⟦c:pacing.split:0.8⟧其实我等你很久了。
```

会渲染成两条消息，中间隔大约 0.9 秒 × 打字节奏。加上 `typewriter` 的逐字浮现，
读起来就像对面的人在犹豫。

**真人不会写小作文。** 这个指令是「像真人」和「像 AI」之间最明显的一条分界线。

不同指令自带不同默认延迟（`CueStreamParser.defaultDelay`）：

| 动作 | 默认停顿 |
|---|---|
| `typewriter` | 0.3s |
| `split` | 0.9s |
| `blush` / `lookaway` / `freeze` | 0.2s |
| 其他 | 0 |

实际停顿还会乘以角色的 `typingTempo` —— 慢性子的人停顿更久。

## 舞台：常驻 vs 瞬时

`StageState` 把特效分两类：

```swift
func apply(_ effect: StageEffect) {
    if effect.isAmbient {
        ambient = effect            // 雨会一直下，直到被换掉
    } else {
        transient.removeAll { $0.name == effect.name }
        transient.append(effect)    // 脸红两秒自己退场
    }
}
```

- **常驻**：rain / snow / night / sepia / blur —— 一次触发，持续存在
- **瞬时**：sparkle / heartbeat / flash / glitch —— 自带生命周期，淡入淡出

瞬时效果的生命周期曲线在 `fadeCurve` 里：前 15% 淡入、中间稳定、后 30% 淡出。
所以不需要外部管理什么时候清理它。

## 特效全是现画的

`Features/Stage/StageEffectLayer.swift` 里 14 种特效，**全部用 Canvas 画**，
零图片素材、零视频文件：

- **雨**：90 条带随机速度的斜线，`time * speed` 取模做循环
- **樱花**：圆角矩形 + 正弦摆动 + 旋转，粉色半透明
- **萤火虫**：径向渐变的光点，亮度按 `sin(time + seed)` 呼吸
- **故障**：横向色带 + 随时间反向漂移，青/品红双色偏移
- **心跳**：随时间缩放并描边的椭圆

这样做的好处：改一个数字就能调强度与密度；不会因为缺素材而降级；
包体积增加 0 字节。

## 强度总闸

`PerformanceDirector.configure(intensityScale:reduceMotion:)`。

设置里那个「演出强度」滑杆（0…1）乘到**所有**指令的强度上，
再乘到特效参数上。调到 0 → `stage.scaled` 返回 0 → 只剩文字。
"减少动态效果"直接短路所有动画与触感。

**同一个滑杆管所有通道** —— 这就是把导演做成一层的直接收益。

## 表演的边界

一条消息的 `shake` 只让那一个气泡抖，不会晃整个界面。
`camera.shake` 才晃界面，而且它通过 `CameraShakeView` 独立承载。

演出要有边界感。全部东西一起动，不叫演出，叫失控。
