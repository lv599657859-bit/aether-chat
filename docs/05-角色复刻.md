# 角色复刻

> 你的要求：**一键准确完美地复刻游戏里的角色，他们会自己去详细搜索并建立自己的知识库。**

「一键」和「准确完美」是一对矛盾：自动的东西最容易编。
这一层的全部设计都在化解这个矛盾 —— **自动，但不盲目**。

## 流水线

```
输入：作品名 + 角色名（+ 别名 + 可选的手动资料）
  │
  ├─ 1. 检索计划（queryPlan）
  │     "角色名" → "作品名 角色名" → "作品名 别名"
  │     先精确后宽泛，避免一上来抓到一堆无关页面
  │
  ├─ 2. 抓取（CanonSourceFetcher）
  │     ├─ Fandom <子域>.fandom.com/api.php   （填了子域才查，但通常资料最全）
  │     ├─ 萌娘百科 zh.moegirl.org.cn/api.php （中文角色首选）
  │     ├─ 维基百科 zh.wikipedia.org/api.php
  │     └─ 手动粘贴（优先级最高）
  │     三家都是 MediaWiki，同一套 action=query&prop=extracts 打通
  │
  ├─ 3. 切块（DocumentChunker）
  │     按段落聚拢到 1800 字，不切断语义
  │
  ├─ 4. 事实抽取（每条资料片段一次 LLM 调用）
  │     十类：identity appearance personality speech ability
  │           relation timeline world taboo quote
  │     硬约束：只抽资料里明确写了的；模糊表述 confidence ≤ 0.4
  │
  ├─ 5. 去重与合并
  │     同一句话被多个来源印证 → confidence +0.15
  │     strict / faithful 下，核心分类 且 confidence ≥ 0.75 → 升级为铁律
  │
  ├─ 6. 冲突检测
  │     身高/年龄/发色/瞳色/生日 出现多种说法 → 提示用户确认
  │
  ├─ 7. 人格还原（buildProfile）
  │     seed（一句话/来历/最想要/最怕/说话方式/态度）
  │   + soul（第二人称正文 150-250 字）
  │   + quirks（口癖）+ taboos + glossary + relationMap
  │   + speechCorpus（原台词样本 —— 学语气，不抄内容）
  │   + openQuestions（资料里没写清楚的）
  │
  └─ 8. 交你审核 → 浇筑（冻结）
```

## 关键设计：它必须会承认自己不知道

`ResearchAgent` 的 prompt 里有这么两句：

> 只抽资料里写了的。没写的一律不要补。**宁可少，不能编。**
> 设定里没有的，不要编。拿不准的写进 openQuestions。

产出结构里的 `openQuestions` 就是它的"我不确定"清单，会在审核页单独列一栏。

**这是「准确」唯一的实现方式**：不是让它知道得更多，是让它在该闭嘴的地方闭嘴。

一个编出来的身高设定，比一个空缺的身高设定有害得多 ——
前者会在某次闲聊里被说出来，然后你发现角色开始说错原作的事，信任整体崩塌。

## 出处可核查

每一条 `CanonFact` 都带 `sources`：

```swift
struct CanonFact {
    var category: Category
    var title: String
    var body: String
    var confidence: Double       // 0...1
    var sources: [CanonSource]   // 带 URL
    var isHard: Bool             // 铁律
    var conflictNote: String?
}
```

知识库查看器（联系人 → 角色 → 查看她的知识库）里每一条都能点开原始链接。

同一句话被越多来源印证，置信度越高 —— 这在 `deduplicate` 里做：

```swift
for source in fact.sources where !existing.sources.contains(where: { $0.url == source.url }) {
    existing.sources.append(source)
}
existing.confidence = min(1.0, existing.confidence + 0.15)
```

## 复核精度这一档在复刻里的作用

| 档位 | 效果 |
|---|---|
| **精确复刻** | 核心分类高置信条目升为铁律，无条件注入；遇到作品未涉及的一律回避 |
| **忠于原作** | 同上，但允许在日常细节上符合性格地延展 |
| **灵感演绎** | 不升铁律，借设定自由发挥 |

## 台词语料为什么单独存

`CanonBundle.speechCorpus` 与 `facts` 分开，因为它们的用途完全不同：

- `facts` 回答「她说什么」—— 事实正确性
- `speechCorpus` 回答「她怎么说」—— 语气、句长、用词习惯

注入时的提示词也刻意区分：

> 【原作里的说话样本 —— 学语气，不要照抄内容】

不写这句话，模型会开始背诵原台词，那就变成一个点读机了。

## 冷门角色怎么办

`ManualFetcher` —— 用户直接粘贴官方设定或剧情文本。

审核页里写得很直白：

> 冷门角色搜不到资料时，粘贴官方设定或剧情文本，
> **复刻质量会显著高于让它自己编。**

这不是妥协，这是正确用法。自动检索是效率工具，不是事实来源。

## 局限

- **只覆盖 MediaWiki 系**。B 站 wiki、灰机 wiki、官方设定集 PDF 目前抓不到。
  加一个 `CanonSourceFetcher` 实现即可扩展（协议只有一个 search + 一个 fetch）。
- **没有图片理解**。角色外貌事实现在只来自文字资料。接入能看图的模型后，
  可以抓角色立绘自动提取外貌描述，锁脸锚点会更准。
- **长资料的抽取是有损的**。现在每个文档最多取前 4 块（约 7200 字）。
  超长设定集需要分批 + 合并策略，这块留给你。
