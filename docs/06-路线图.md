## 接下来该做的（按优先级）

### P0 · 让它在真机上一次跑通

1. **首次编译修错**。这个工程在 Windows 上写、没编译过。
   预期需要修的地方：actor 隔离标注、Optional 展开、SwiftUI 泛型推断。
   建议一次性 `⌘B` 收集全部错误再统一改。
2. **后台自主性换 BGTaskScheduler**。现在 `AutonomyScheduler` 靠前台定时器跑，
   切后台就停。改成 `BGAppRefreshTask`（标识符已在 Info.plist 配好）。
3. **推送**。角色主动发消息时不推送，用户只有打开 app 才知道 —— 体验断层。
   需要 APNs + 服务端调度，或者至少本地通知。

### P1 · 让演出真的惊艳

4. **接入 Live2D**。拿到 Cubism 授权后实现 `Live2DModelBridge`（约 30 行）。
   这是 2D 表现力上限的关键一步。
5. **VRM 转换工具链**。写一个 macOS 端小工具，把 .vrm 批量转 USDZ 并
   规范具名部件（`Expr_*` / `Mouth_*`）。
6. **口型同步升级**。现在是正弦波模拟。接 TTS 的音素时间戳后，
   可以让嘴型真的对上音节。
7. **环境音素材**。雨、咖啡馆、电车、风 —— 放进 `Bundle/Audio/` 就自动生效。
8. **立绘素材生成**。用 ImageStudio 的锁脸锚点批量生成一组表情差分，
   用户不用自己画就能得到一套可用的 2D 立绘。

### P2 · 让长期使用不出问题

9. **存储换 GRDB**。JSON 在几万条消息后会开始卡。`WorldStore` 接口不用动。
10. **动态上下文预算**。现在是固定分配，改成按当前轮需求调档。
11. **摘要质量监控**。摘要错了会导致角色"记错事"，需要一个自检机制
    （比如定期从摘要回放关键事实，和记忆比对）。
12. **关系引擎用模型评分**。现在靠关键词词典，够用但粗糙。
    用一个小模型给每轮对话打情感分，关系演化会更细腻。
13. **数据导出/导入**。`FileStore.exportArchive` 已经写了，缺 UI。

### P3 · 让复刻更准

14. **更多资料源**。B 站 wiki、灰机 wiki、官方设定集 PDF。
    实现 `CanonSourceFetcher` 即可（协议只有两个方法）。
15. **图片理解**。抓角色立绘，让多模态模型提取外貌描述，锁脸锚点更准。
16. **超长资料分批**。现在每个文档只取前 4 块。
17. **设定冲突的人工裁决 UI**。现在只提示冲突，没给解决入口。

### 最后一条展开说

`ContextEngine.renderForModel` 里，历史图片被渲染成 `（发来一张图片）`：

```swift
case .image, .dailyShare:
    let caption = message.attachments.first?.caption ?? ""
    text = caption.isBlank ? "（发来了一张图片）" : "（发来一张图片）" + caption
```

也就是说：**角色记得住"你发过图"，但记不住图里是什么**。

修的办法是让 `Message.hidden` 存一份图片的文本描述（发图时用
`ImageStudio.describeIncoming` 生成），retrieval 时把它当普通文本注入。
工作量不大，但会影响每一轮的 token 预算，所以先标出来。
